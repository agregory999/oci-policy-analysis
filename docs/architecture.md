# Architecture

The Python package provides desktop, CLI, FastAPI web, and FastMCP interfaces over shared IAM policy analysis services and reference data. The web UI uses static JavaScript and HTTP routes; MCP tools expose bounded search and analysis calls. OCI client operations use the existing application service and repository layers. Loaded tenancy data may contain group names, policies, compartments, and identity-domain metadata; local caches and logs should be handled as sensitive operational data.

The default container deployment builds two images from the checkout, each with its own optional dependencies. The explicitly selected PyPI build installs an exact published package version using a docker-only context; local application source is excluded. Both paths share launch scripts and the deployment configuration. A configured Container Instance runs web, MCP, or both. Ports default to 8000 and 8765; the current combined deployment uses 8000 and 8001. The workload uses Resource Principal and the web UI is locked to that identity. OCI CLI and Docker credentials stay with the operator; they are not passed to the containers. The existing Load Balancer, networking, IAM, OCIR repository, and backend configuration are owned outside these scripts. The deploy script only creates or explicitly replaces the named Container Instance. Its delete/create replacement has downtime and may lose the previous private IP.

`/health` on each port reports process health. OCI CLI errors, container lifecycle, logs, and Load Balancer backend health are the deployment diagnostics. PyInstaller executable packaging and uv source builds now share the same configuration loader; package publishing remains separate. This mixed-interface project is an exception to the skill's single-format starter layout.

The operator requested `run-build/.env` as the single sourceable configuration, an explicit exception to the skill's default `run/.env` location and headings. `run/.env.example` links to the canonical `run-build/.env.example`; all executable operations remain in `run/`. Shell exports override the file and command flags override startup defaults. Web/desktop preferences remain in the existing saved settings file. Containers receive only their own launch variables; MCP uses the single depth variable `MCP_COMPARTMENT_DOMAIN_SEARCH_DEPTH`. Disabled OAuth values, UI preferences and diagnostics are not forwarded. Replacement compares runtime environments as well as images, so a domain depth change cannot silently be skipped. Identity-domain depth 2 includes root and immediate child compartments; this is independent of recursive policy loading.

The optional published-release path is an operator-requested exception to the local-source-only build convention. `run/build-push-image.sh` always selects source; `run/build-push-pypi.sh` explicitly selects the `OPA_VERSION` release, without changing the deploy script. Record operations Git revision, package version, tags and pushed digests for traceability.
